# 为什么选择 Knotlog

> 本译文由机器辅助完成，欢迎指正。

## 问题

今天打开一个终端智能体，它对昨天一无所知。

昨晚你和它花了三个小时。你讲清了项目，否决了两种方案并说明了理由，
最后敲定了第三种。今天早上你在同一个文件夹里打开同一个智能体，
这一切都不见了。于是你又解释一遍。这次更简短，因为你已经厌倦了解释，
也就意味着它拿到的是更差的版本。

整个问题就是这样。不是模型弱——模型没问题。
只是它每次会话都从零开始，而你是那个替它把上下文带过这道鸿沟的人。

这样过了几周，你会注意到自己开始做的事：
你留着一个草稿文件，里面是开头要粘贴的内容。
你避免开很长的会话，因为重启的代价太高。
你不再问“我们当初为什么这么做”，因为没有人记得，包括你自己。

## Knotlog 的做法

Knotlog 把发生过的事用 Markdown 记在一个文件夹里。

智能体工作时，它读取或写入的每个文件都会作为一行追加到
日志中。会话结束时，这些行变成一份带日期的笔记。下一次
会话开始时，最近的活动和未完成的线索会在你输入任何内容之前
被打印回模型的上下文。

所以明天早上，智能体一开场就知道你昨晚做了什么、为什么这么做。
不是因为它记得——而是因为它读到了。

这就是全部的想法。本页其余部分讲的是它为什么要这样构建。

## 为什么它不花钱

人们最先问的就是这一点，因为大多数编码智能体的记忆工具
都要为基础设施收费。

它们收费是有原因的。像 claude-mem 这样的工具会运行一个单独的 worker 进程
来判断一次会话意味着什么。那个 worker 内部没有模型，所以得从别处
借一个：检索要用向量数据库，填充它要用嵌入，
生成嵌入要用 API 密钥。真正的基础设施，真正的成本，转嫁给了你。

Knotlog 没有这个问题，因为它从来不需要第二个大脑。智能体本来就在运行，
你本来就在为它付费。所以理解语义的那一部分，就是你循环里已有的模型——
Knotlog 只是给它一个地方记下东西，并在恰当的时刻把它们读回来。

没有数据库。没有嵌入。没有 API 密钥。没有什么可向你收费的，
因为根本没有任何会产生费用的东西在运行。

## 文件是你的

你的记忆就是你选定的文件夹里的 Markdown 文件。

用任何编辑器打开它们。完全不借助任何工具也能阅读。把它们放进 git，
看着你自己的思考在几个月里发生变化。五年后把它们搬进 Obsidian，
或者另一个记忆工具，或者一个纯文本编辑器。

没有什么需要导出，因为从来没有东西被导入到只有一个程序才能读的格式里。
Knotlog 向这些文件追加内容；它绝不改写你写下的东西。
如果你明天删掉 Knotlog，它记录的一切仍然躺在那里，依然可读。

## 离线，且在本地

Knotlog 不发起任何网络调用。里面没有 `curl`，没有上传，没有遥测，
没有账号。

你的笔记在你的磁盘上。你的智能体凌晨 2 点碰过什么，也在你的磁盘上。
如果你处理客户代码、受保密协议约束的内容，或者在飞机上工作，这一点很重要。
这也意味着 Knotlog 不会因为某个服务宕机、改了定价或取消了免费额度而失灵。

## 零依赖

Knotlog 是一个 POSIX shell 脚本。它用 `sed`、`awk`、`grep`、`tr` 和 `git`——
都是你的机器上本来就有的工具。

没有 Python。没有 Node。没有 `jq`。没有什么要 `npm install`，没有什么要与运行时版本
保持同步，也没有什么会在六个月后你升级一个无关的东西时坏掉。

这不是在吹嘘极简主义。这正是安装能成功的原因。
没有需要解析的依赖树，所以安装没有什么可以失败的地方。
测试套件在每次提交时都会在 Linux、macOS 和 Windows 上运行，
因为同一个脚本在三者上运行。

## 土耳其语和英语，都做到位

大多数工具把非英语当作最后才套上去的翻译层。这里的做法
比界面字符串深入得多。

搜索在建立索引之前和查询之前都会对文本做折叠。在土耳其语知识库中，
`İ ı ğ ş ç ö ü` 在两侧都折叠为各自的 ASCII 形式，所以 `acik kaynak` 和
`açık kaynak` 能找到同一条笔记。这个折叠是一张真正的字符映射表，逐条规则写出——
而不是一个寄希望于运气的 `lowercase()` 调用，把带点的 İ 弄得面目全非
还说“搞定了”。

界面、文件夹布局、帮助文本、预置模板和伙伴人设都有两种语言的版本。
你在安装时选一种，知识库就用它来建立。

## 它不是什么

Knotlog 不是一个能理解你文字的搜索引擎。它的搜索是词法的，
用 BM25 排序——擅长找到你记得一半的笔记，不擅长
回答关于它的问题。理解发生在它该发生的地方：读取结果的模型里。

Knotlog 也不会替你写反思。它以机械方式记录发生了什么——
文件、时间、工具——并在每份会话笔记中留下一个骨架，
给只有你或模型才能补上的部分：改了什么，以及为什么。如果没人
去填，就没人填。Knotlog 强制的是格式，不是含义。

它也不会读懂你对结构的想法。它为你写下的笔记建立索引。
它不会凭空发明笔记。

## 坦白的总结

如果你每天都使用编码智能体，你就已经有了记忆问题。
你已经在手动解决它，而且做得很糟糕——靠粘贴上下文和一个草稿文件。

Knotlog 是一个小脚本，替你做这件事，写进你拥有的文件里，
运行在依然属于你的机器上，而且不花一分钱。
