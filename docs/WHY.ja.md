# なぜ Knotlog なのか

> この翻訳は機械支援によるもので、修正を歓迎します。

## 問題

今日、ターミナルのエージェントを開いても、昨日のことは何も知りません。

昨夜、あなたは 3 時間をかけてエージェントと作業しました。プロジェクトを説明し、2 つのアプローチを理由付きで却下し、3 つ目に決めました。
今朝、同じフォルダで同じエージェントを開くと、そのどれも残っていません。そこでもう一度説明することになります。
説明に疲れているので、今度は短くなり、結果として質の落ちた説明になります。

問題はこれがすべてです。モデルが弱いわけではありません。モデルは十分に優秀です。ただ、毎回のセッションをゼロから始めるだけで、
その断絶をまたいでコンテキストを運んでいるのはあなたです。

数週間これを続けると、自分がやり始めていることに気づきます。冒頭に貼り付けるためのメモ用ファイルを持つようになります。
再起動のコストが高いので、長いセッションを避けるようになります。
「なぜこうしたんだっけ」と聞くこともやめます。あなたも含めて、誰も覚えていないからです。

## Knotlog の代わりのやり方

Knotlog は、起きたことを 1 つのフォルダに Markdown で書き留めます。

エージェントが作業している間、読み書きしたすべてのファイルが、1 行ずつログに追記されます。セッションが終わると、それらの行は日付付きのノートになります。
次のセッションが始まると、あなたが何かを入力する前に、直近の活動と未解決のスレッドがモデルのコンテキストに出力されます。

だから明日の朝、エージェントは昨夜あなたが何をしたか、そしてなぜそうしたのかを知った状態で始まります。
覚えているからではありません。読むからです。

アイデアはこれがすべてです。このページの残りは、なぜこのような作りになっているのかの説明です。

## なぜ無料なのか

最初に聞かれるのはここです。コーディングエージェント向けのメモリツールの多くは、インフラに課金するからです。

それには理由があります。claude-mem のようなツールは、セッションが何を意味したのかを判断するために、別個のワーカープロセスを動かします。
そのワーカーの中にはモデルがないので、どこかから調達しなければなりません。検索のためのベクトルデータベース、それを埋めるための埋め込み、
それを生成するための API キー。本物のインフラ、本物のコストで、それがあなたに転嫁されます。

Knotlog にはその問題がありません。第二の頭脳を必要としたことがないからです。エージェントは既に動いています。あなたは既にその料金を払っています。
そのため、意味を理解する部分は、既にループの中にいるモデルです。Knotlog は、そのモデルが書き留める場所を用意し、適切なタイミングで読み返すだけです。

データベースなし。埋め込みなし。API キーなし。課金するものは何もありません。お金がかかり得るものが何も動いていないからです。

## ファイルはあなたのもの

あなたのメモリは、あなたが選んだフォルダの中の Markdown ファイルです。

好きなエディタで開けます。ツールを一切使わずに読めます。git に入れて、数か月にわたる自分の思考の変化を眺められます。
Obsidian や別のメモリツール、あるいは 5 年後のプレーンテキストエディタにも移せます。

エクスポートするものは何もありません。1 つのプログラムしか読めない形式に取り込まれたものは、何もないからです。Knotlog はこれらのファイルに追記するだけで、
あなたが書いたものを書き換えることはありません。明日 Knotlog を削除しても、記録されたものはすべてそこに残り、読めるままです。

## オフライン、そしてローカル

Knotlog はネットワーク呼び出しを一切行いません。`curl` もなく、アップロードも、テレメトリも、アカウントもありません。

あなたのノートはあなたのディスクにあります。午前 2 時にエージェントが触ったものも、あなたのディスクにあります。
クライアントのコードや NDA の対象となるもの、あるいは飛行機の中で作業するときに、これは重要です。
またそれは、サービスが落ちたり、価格が変わったり、無料枠が終了したりしても、Knotlog が壊れないことも意味します。

## 依存関係ゼロ

Knotlog は 1 つの POSIX シェルスクリプトです。使うのは `sed`、`awk`、`grep`、`tr`、`git` で、どれもあなたのマシンに既にあるツールです。

Python なし。Node なし。`jq` なし。`npm install` するものも、ランタイムのバージョンと同期を保つものもなく、
6 か月後に無関係な何かをアップグレードしたときに壊れるものもありません。

これはミニマリズムの自慢ではありません。インストールが成功する理由です。解決すべき依存関係ツリーがないので、インストールが失敗する原因もありません。
同じスクリプトが 3 つすべてで動くため、テストスイートは毎回のコミットで Linux、macOS、Windows 上で実行されます。

## トルコ語と英語、どちらもきちんと

多くのツールは、英語以外を最後に取り付ける翻訳レイヤーとして扱います。ここでは、インターフェースの文字列よりも深いところまで対応しています。

検索は、インデックス作成の前とクエリの前にテキストをフォールディングします。トルコ語のボールトでは、両側で `İ ı ğ ş ç ö ü` が ASCII 形に畳み込まれるので、
`acik kaynak` と `açık kaynak` は同じノートを見つけます。このフォールドは、規則を 1 つずつ書き出した本物の文字マップです。
ドット付きの İ を壊して終わりにする、期待頼みの `lowercase()` 呼び出しではありません。

インターフェース、フォルダレイアウト、ヘルプテキスト、シードされるテンプレート、コンパニオンのペルソナは、どちらの言語にも用意されています。
インストール時に 1 つを選ぶと、ボールトはその言語で作られます。

## Knotlog がやらないこと

Knotlog は、あなたの文章を理解する検索エンジンではありません。検索は字句検索で、BM25 でランク付けされます。うろ覚えのノートを見つけるのは得意ですが、
それについての質問に答えるのは得意ではありません。理解は、本来あるべき場所、つまり結果を読むモデルの中で起こります。

また、Knotlog はあなたの振り返りを代わりに書きません。起きたこと (ファイル、時刻、ツール) は機械的に記録し、あなたかモデルにしか埋められない部分、
つまり何が変わったか、そしてなぜかのために、各セッションノートにひな形を残します。誰も埋めなければ、誰も埋めません。Knotlog が強制するのは形式であって、意味ではありません。

そして、構造について心を読むこともしません。あなたが書いたノートをインデックスします。ノートを作り出すことはありません。

## 正直なまとめ

コーディングエージェントを毎日使っているなら、あなたには既にメモリの問題があります。そして貼り付けたコンテキストとメモ用ファイルで、既に手作業で、下手に解決しています。

Knotlog は、その部分を代わりにやってくれる小さなスクリプトです。あなたが所有するファイルへ、あなたのものであり続けるマシンの上で、無料で。

ここから始めてください。インストールは [README](../README.ja.md)、日々の流れは[ユーザーガイド](GUIDE.ja.md)です。
